# E5-S1: Refund request endpoint

- **Epic:** E5 - Refunds
- **Layer:** API
- **Group:** E
- **Depends on:** E2-S4, E1-S3

## Description

Lets a customer request a full refund of a COMPLETED payment, enforcing one refund per payment, and lists refunds by role.

## Acceptance Criteria

1. POST /refunds with a COMPLETED own payment returns 201 with state REQUESTED, amount_paise equal to the payment amount and requested_by equal to the customer id, and appends a REFUND_REQUESTED event (feature F073)
2. A payment in CREATED, SUBMITTED or FAILED is rejected with 422 and code PAYMENT_NOT_REFUNDABLE (feature F074)
3. A second request for the same payment returns 409, and 10 concurrent requests create exactly one refund (feature F075)
4. Requesting a refund on another customer's payment returns 404, and ops or admin calling POST /refunds returns 403 (feature F076)
5. GET /refunds returns only the caller's refunds for a customer, and all refunds with ?state= filtering for admin (feature F077)
