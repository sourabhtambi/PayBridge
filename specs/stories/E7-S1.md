# E7-S1: Settlement CSV generation

- **Epic:** E7 - Settlement
- **Layer:** Service
- **Group:** F
- **Depends on:** E6-S1

## Description

Generates one combined, append-only settlement CSV per IST business date, with unmatched flags, a row count and a SHA-256 checksum. Late entries go to a separate follow-up file.

## Acceptance Criteria

1. The file for a business date has one row per COMPLETED payment of that IST day with columns payment_id, rail, amount_paise, rail_ref, recon_status and unmatched_flag; a payment at 18:29:59Z belongs to that date and one at 18:30:00Z to the next (feature F106)
2. Unmatched and amount_mismatch rows are included with unmatched_flag true and do not block generation (feature F107)
3. The file ends with a footer holding row_count and a SHA-256 checksum that equals the recomputed checksum of the data rows, and a SettlementFile record with kind primary is stored (feature F108)
4. A second run for the same date does not overwrite the primary file (identical bytes and checksum) (feature F109)
5. Entries completed after the primary file go to a follow-up file with kind followup containing only entries absent from the primary, and no follow-up is created when there are none (feature F110)
