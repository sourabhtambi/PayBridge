# E1-S2: SQLite schema and repositories

- **Epic:** E1 - Foundation and Role Switch
- **Layer:** Repository
- **Group:** B
- **Depends on:** E1-S1

## Description

Creates the nine-table SQLite schema in WAL mode with the uniqueness and append-only guarantees the later stories rely on. Provides repository classes per entity and seeds demo customers.

## Acceptance Criteria

1. Initialising a fresh database creates tables customers, payments, payment_attempts, outbox_messages, payment_events, refunds, rail_statement_entries, reconciliation_results and settlement_files, and PRAGMA journal_mode returns 'wal' (feature F006)
2. Inserting two payments with the same (customer_id, idempotency_key) raises DuplicateKeyError, and inserting a second refund for one payment_id raises DuplicateKeyError (feature F007)
3. payment_events has no update or delete repository methods, and a raw UPDATE or DELETE on payment_events fails with a trigger error (feature F008)
4. amount_paise columns are INTEGER with CHECK (amount_paise >= 100), and inserting 99 fails (feature F009)
5. Seeding creates 3 customers, 1 ops user and 1 admin user and is idempotent when run twice (feature F010)
