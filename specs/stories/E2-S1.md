# E2-S1: Payment creation service with routing and outbox

- **Epic:** E2 - Payment Creation and Idempotency
- **Layer:** Service
- **Group:** C
- **Depends on:** E1-S1, E1-S2

## Description

Implements the service that validates a payment request, routes it to a rail and persists the payment, an outbox message and the first event in one transaction. This is the core of the MVP.

## Acceptance Criteria

1. Creating a payment of 150000 paise stores a CREATED payment with rail UPI, one pending outbox message and one PAYMENT_CREATED event, all in one transaction (feature F020)
2. If the outbox insert fails, no payment row and no event row remain (transaction rolled back) (feature F021)
3. An amount of 10,000,001 paise routes to IMPS and 50,000,001 routes to RTGS in the stored payment (feature F022)
4. A request with amount 99 paise, or an empty beneficiary, or a beneficiary longer than 140 characters is rejected with a validation error and persists nothing (feature F023)
