# E3-S1: New payment form with rail preview

- **Epic:** E3 - Customer Payment Screens
- **Layer:** UI
- **Group:** F
- **Depends on:** E2-S3, E1-S4

## Description

Builds the customer form to create a payment, previewing the rail as the amount is typed and handling every API outcome defined in BRD 12.3.

## Acceptance Criteria

1. The form has labelled Amount (Rs) and Beneficiary fields, and an idempotency key (UUID) generated per form session and regenerated after a successful new submission (feature F038)
2. The rail preview shows UPI for 1,00,000, IMPS for 100000.50, NEFT for 200000.01 and RTGS for 500000.01, and shows no rail for 0.99 (feature F039)
3. A 422 response shows the field message 'Amount must be at least Rs 1' beside the amount field, and zero or negative amounts show a field error before submit (feature F040)
4. A 409 shows 'This request was already submitted with different details. Start a new payment.', a 200 replay shows 'This payment was already created. Showing the original.' and navigates to /payments/{id}, and a 202 navigates to /payments/{id} (feature F041)
5. The submit button is disabled with a progress label while pending, and 1,00,000.50 is sent as 10000050 paise via string parsing, not floating point (feature F042)
