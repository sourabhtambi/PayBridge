# E1-S3: Role switch middleware, customers endpoint and health check

- **Epic:** E1 - Foundation and Role Switch
- **Layer:** API
- **Group:** C
- **Depends on:** E1-S2

## Description

Adds header-based role resolution, role guards and the endpoints needed before any business endpoint: health and the customer list for the picker. The role switch is demo-only and not a security control.

## Acceptance Criteria

1. GET /health returns 200 with body {"status":"ok"} and a database check field, without requiring role headers (feature F011)
2. A protected endpoint called without X-Role returns 401, and with X-Role set to an unknown value returns 401 (feature F012)
3. X-Role: customer without X-Customer-Id, or with an unknown customer id, returns 401; a valid pair resolves the customer (feature F013)
4. Role guards return 403 when a role calls an endpoint outside its permissions (customer calling /admin/simulation returns 403) (feature F014)
5. GET /customers returns the seeded customers with id, name and role for all three roles, and CORS allows origin http://localhost:3000 with headers X-Role, X-Customer-Id and Idempotency-Key (feature F015)
