# E2-S3: Payments API endpoints

- **Epic:** E2 - Payment Creation and Idempotency
- **Layer:** API
- **Group:** E
- **Depends on:** E2-S2, E1-S3

## Description

Exposes payment creation, detail and listing over HTTP with the status codes defined in BRD 8.8. Role scoping ensures customers only see their own payments.

## Acceptance Criteria

1. POST /payments with Idempotency-Key and a valid body returns 202 with id, state CREATED, rail and amount_paise (feature F029)
2. A replay returns 200 with the original id, a payload mismatch returns 409, amount 99 returns 422 with a field error on amount, and a missing Idempotency-Key returns 422 (feature F030)
3. GET /payments/{id} returns the payment with events and attempts arrays; another customer's payment returns 404; ops and admin can read any payment (feature F031)
4. GET /payments returns only the caller's payments newest first for a customer, supports ?state=, and ops/admin see all payments with optional ?customer_id= (feature F032)
5. POST /payments as ops or admin returns 403 (feature F033)
