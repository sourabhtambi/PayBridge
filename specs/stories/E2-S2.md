# E2-S2: Idempotent payment creation

- **Epic:** E2 - Payment Creation and Idempotency
- **Layer:** Service
- **Group:** D
- **Depends on:** E2-S1

## Description

Adds idempotency on top of payment creation using a stored request hash and the unique (customer_id, idempotency_key) constraint. Targets success metric M1: exactly one payment per key under replay and concurrency.

## Acceptance Criteria

1. Replaying the same key and payload returns the original payment flagged as replay, and only one payment row exists (feature F024)
2. The same key with a different amount or different beneficiary raises IdempotencyConflict and creates no new row (feature F025)
3. 20 concurrent create calls with the same key and payload create exactly one payment and 19 replays (feature F026)
4. The same key used by two different customers creates two separate payments (feature F027)
5. A key older than 24 hours (injected clock) is treated as expired: the same key with the same payload creates a new payment and the original is unchanged (feature F028)
