# E5-S2: Refund approval, rejection and execution

- **Epic:** E5 - Refunds
- **Layer:** API
- **Group:** F
- **Depends on:** E5-S1, E4-S1

## Description

Lets an admin approve or reject a refund. Approval executes a rail-level reversal through the mock adapter and records the outcome. There is no account credit.

## Acceptance Criteria

1. POST /refunds/{id}/approve moves REQUESTED to APPROVED then EXECUTED via the adapter reversal, sets decided_by to the admin id and appends REFUND_EXECUTED (feature F078)
2. POST /refunds/{id}/reject sets REJECTED with decided_by, and the payment remains COMPLETED (feature F079)
3. Approving or rejecting an already decided refund returns 409 REFUND_ALREADY_DECIDED, and two concurrent approvals result in one success and one 409 (feature F080)
4. A permanent adapter failure on reversal sets the refund FAILED with the reason code and leaves the payment COMPLETED (feature F081)
5. Approve and reject return 403 for customer and ops and 404 for an unknown refund id (feature F082)
