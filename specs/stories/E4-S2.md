# E4-S2: Retry with exponential backoff and failure handling

- **Epic:** E4 - Retry and Failure Simulation
- **Layer:** Service
- **Group:** F
- **Depends on:** E4-S1

## Description

Extends the worker so transient errors retry up to 5 attempts with 1s doubling delay, and permanent errors fail the payment immediately with a reason code.

## Acceptance Criteria

1. Two transient failures then a success complete the payment on attempt 3 with attempts recorded as transient, transient, success (feature F056)
2. Retry delays between attempts are 1, 2, 4 and 8 seconds, reflected in outbox next_attempt_at (feature F057)
3. Five consecutive transient failures set the payment to FAILED with reason code RETRIES_EXHAUSTED and exactly 5 attempts (feature F058)
4. A permanent failure with INSUFFICIENT_FUNDS sets FAILED immediately with that reason code and exactly 1 attempt (feature F059)
5. Each retry scheduling and each failure appends PAYMENT_RETRY_SCHEDULED and PAYMENT_FAILED events respectively (feature F060)
