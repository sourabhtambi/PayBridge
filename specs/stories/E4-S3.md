# E4-S3: Crash recovery for in-flight outbox rows

- **Epic:** E4 - Retry and Failure Simulation
- **Layer:** Service
- **Group:** G
- **Depends on:** E4-S2

## Description

Makes the worker resume unsent or in-flight outbox rows after a restart, relying on rail-side deduplication by payment id to avoid duplicate submissions.

## Acceptance Criteria

1. An outbox row left IN_PROGRESS at startup is resumed after a simulated restart and its payment reaches a terminal state (feature F061)
2. If the process dies after the rail accepted but before the database update, the resumed submission returns the same rail reference and the rail holds exactly one entry for that payment (feature F062)
3. The worker never processes an outbox row before its next_attempt_at (feature F063)
4. Killing the worker mid-batch of 10 payments and restarting results in all 10 reaching a terminal state exactly once (feature F064)
